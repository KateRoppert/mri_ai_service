## Setup

Full pipeline (stages 01–08) per set, two orders × two repeats, worktree code
in throwaway containers (`--memory 9g`, no Kappa upload, empty DB):

- **after** — today: skull-on `t1` → MNI152 (rigid, no seed), HD-BET on the
  registered image.
- **before** — HD-BET on the native N4 `t1` (≤1 mm copy), brain →
  `MNI152_T1_1mm_brain` (rigid, seed 42), mask warped to atlas (linear + 0.5).

| Set | Lesion | Patients / sessions analysed |
|---|---|---|
| SibBMS P000010, P000063, P000067 | MS | 3 / 11 (2D thick-slice + 3D 0.35 mm) |
| MS_5 P000915 | MS | 1 / 2 |
| dropbox_33 (first 6 of the SS-research calibration sample) | GBM | 6 / 6 |
| clinical BO (seeded random 6) | GBM | 6 / 5 complete |
| UPENN-GBM | GBM | 3 / 3 — registration only (see caveats) |

No ground truth for registration exists, so three independent proxies are
used; they agree. Medians [range].

Better in every session and every patient, and repeatable; the largest gains
are on clinical MS (2D) and clinical GBM. UPENN — already near-canonical
acquisitions — barely changes.

### Brain masks

Volumes are the same in both orders (SibBMS 1386 vs 1381 ml, dropbox 1394 vs
1384, BO 1397 vs 1394, UPENN 1460 vs 1459, MS_5 1169 vs 1171). Stripping in
native space does not change what HD-BET calls brain.

### Lesion segmentation — native space is unaffected

| Set | native lesion Dice: repeat (after) / repeat (before) / **after vs before** | |volume change| after→before |
|---|---|---|
| SibBMS | 0.84 / 0.86 / **0.85** | 2 % [0–6] |
| MS_5 | 0.84 / 0.84 / **0.85** | 1 % |
| dropbox_33 | 0.97 / 0.98 / **0.97** | 1 % [0–3] |
| BO | 0.97 / 0.98 / **0.97** | 0 % (one 0.01 ml mask: 48 %) |

Switching order changes the native lesion masks no more than re-running the
same order does. The segmentation models are robust to the registration
error; native-space results produced so far are not invalidated.

### Anatomical localisation — atlas space changes a lot

Share of lesion volume that lands in a **different** lobe / McDonald zone:

| Set | repeat (after) | repeat (before) | **after vs before** |
|---|---|---|---|
| SibBMS — McDonald zones | 0.02 [0–**0.92**] | 0.01 [0–0.08] | **0.54** [0.01–0.93] |
| MS_5 — McDonald zones | 0.13 [0.01–0.24] | 0.00 | **0.77** [0.53–1.00] |
| dropbox_33 — lobes | 0.01 [0–0.14] | 0.01 [0–0.02] | **0.31** [0.06–0.45] |
| BO — lobes | 0.01 [0–0.10] | 0.00 [0–0.04] | **0.11** [0.05–0.73] |

Lobar and McDonald reports depend on the atlas registration directly.
Today's order makes them both wrong (the registration is off) and unstable
(up to 92 % of an MS session's lesion volume moves zone between two identical
runs). With `before` they are stable, and the registration they rest on is
measurably closer to the template.

### Cost

Stage 05 per session: GBM 68 → 76 s, UPENN 56 → 59 s, MS 125–130 → 134–143 s
(+5–10 %). Peak memory unchanged (3D MS session 8.2 GB either way).

## Caveats

- **3D SibBMS sessions (P000067 ses-005/006)** were OOM-killed in 3 of 4
  first-pass runs, in both orders (6.4–6.8 GB free with both segmentation
  services resident). Re-run one at a time on 2026-10-09 with nothing else
  running — all 4 runs now have all 11 sessions; the numbers above include them.
- Found while re-running (not caused by the experiment):
  - a second web instance built from a git worktree has **no segmentation
    weights** (they are git-ignored), so its stage 06 gets HTTP 503 — the
    re-run used the main stack's `ms-seg`;
  - two UI starts 40 s apart **both ran into the same output folder**; the
    one-active-run-per-output guard did not stop the second;
  - two pipelines plus the re-run at once exhausted host memory (global OOM
    killed a VS Code process) — run one pipeline at a time on this laptop.
- **UPENN: no segmentation.** Stage 01 took a diffusion series (with
  `.bval`/`.bvec`) as `t2`, so every session lacks a real T2 and stage 06
  skips it — a stage 01 classification bug, independent of this experiment
  (new KI). Registration and masks are compared.
- Small sample (27 sessions, 13 patients). Proxies, not ground truth — but
  three independent ones agree in every case.
- 2D thick-slice sessions keep slice-thick steps at the mask edge and, when
  the slab does not cover the whole head, a flat cut at its edge — data
  limits, identical in both orders.

## Recommendation

1. Make `before_registration` the production order (change the default),
   after the 3D re-run confirms it on the two big sessions.
2. Regenerate every atlas-space result already produced (lobar / McDonald
   reports, longitudinal comparisons, what is in Kappa). Native-space lesion
   masks and volumes are fine.
3. Skull-stripping research: compare tools on the **native-space** skull-on
   input — that is what production will strip. `mni_mask` stays a baseline
   only (it needs a registration to exist).
